## 2. 한 줄 설명

본 서비스는 Binance 기반 ETH/USDT 시장 데이터를 수집하고, 기술지표 및 머신러닝 기반 예측을 조합하여 현재 시장 상태와 매매 의사결정 보조 신호를 제공하는 분석형 트레이딩 대시보드이다.

---

## 3. 서비스 배경

본 프로젝트는 초기에는 실험적 성격으로 다양한 기능을 빠르게 추가하면서 확장되었다.  
그 과정에서 기능은 많아졌지만 서비스 정의, 범위, 우선순위, 요구사항, 화면 구성 원칙 등이 명확히 정리되지 않았다.

그 결과 다음과 같은 문제가 발생했다.

- 현재 서비스가 정확히 무엇인지 한 문장으로 설명하기 어렵다.
- 구현된 기능과 문서상 기능이 일치하지 않는다.
- 제품 범위가 “분석 도구”인지 “실제 트레이딩 플랫폼”인지 모호하다.
- 기능 추가 시 우선순위 판단 기준이 없다.
- 향후 리팩터링/확장/삭제 판단이 어려워진다.

본 문서는 이 문제를 해결하기 위해 현재 코드 기준으로 서비스 정체성을 재정의하기 위해 작성한다.

---

## 4. 서비스 목적

본 서비스의 목적은 사용자가 ETH/USDT 시장 데이터를 기반으로 다음을 더 쉽게 할 수 있도록 지원하는 것이다.

1. 현재 시장 상태를 빠르게 파악한다.
2. 기술지표와 ML 예측 결과를 함께 확인한다.
3. LONG / SHORT / NO-TRADE 성격의 보조 신호를 확인한다.
4. 신호의 신뢰도와 과거 성과를 검토한다.
5. 데이터 수집/모델 상태/운영 이상 여부를 확인한다.

## 6. 핵심 제공 가치

본 서비스는 사용자에게 아래 가치를 제공한다.

### 6.1 시장 상황 통합 확인
가격, 거래량, 기술지표, 예측 결과, 신호를 하나의 대시보드에서 본다.

### 6.2 판단 보조
기술지표만 보거나 예측만 보는 것이 아니라, 둘을 결합한 종합 신호를 확인한다.

### 6.3 신뢰도 검토
예측 결과와 실제 결과를 비교해 모델이 얼마나 쓸만한지 판단한다.

### 6.4 운영 가시성
데이터 수집이 정상인지, 모델이 준비되었는지, 파이프라인이 늦는지 확인할 수 있다.

## 7. 서비스 범위

### 7.1 현재 포함 범위
- Binance 기반 시세 데이터 수집
- 15분 봉 OHLCV 저장
- 기술지표 계산 및 저장
- ML 분류/회귀 기반 예측
- 앙상블 신호 생성
- 신호 이력 조회
- 예측 정확도 추적
- 모델 학습 수동 트리거 및 상태 확인
- 운영 상태 확인
- 대시보드 UI 제공

### 7.2 현재 제외 범위
- 실제 주문 실행
- 포지션 체결/정산
- 사용자 인증/권한
- 결제/구독
- 멀티유저 협업
- 다중 거래소 통합 운영
- 자동매매 봇 배포/관리

## 8. 서비스 성격 정의

본 서비스는 현재 단계에서 다음과 같이 정의한다.

### 8.1 제품 성격
**분석형 트레이딩 대시보드**

### 8.2 제품 역할
**매매 의사결정 보조 도구**

### 8.3 제품 비역할
**실거래 실행 엔진 아님**

이 정의를 기준으로 기능 추가 여부를 판단한다.

예를 들어:
- “현재 시장 상태를 더 잘 보여주는가?” → 포함 가능
- “신호 품질을 더 높이는가?” → 포함 가능
- “실주문/체결/잔고 관리 기능인가?” → 현재 범위에서는 제외

---

## 9. 핵심 사용자 시나리오

### 시나리오 A. 현재 신호 확인
사용자는 대시보드에 접속한다.  
가격 차트, 기술지표, ML 예측, 현재 신호, TP/SL 제안값을 확인한다.  
이를 바탕으로 진입 여부를 판단한다.

### 시나리오 B. 과거 신뢰도 검토
사용자는 최근 신호 이력과 예측 정확도 패널을 확인한다.  
현재 신호가 최근에도 유효했는지 참고한다.

### 시나리오 C. 모델 재학습
운영자는 학습 패널에서 ML 학습을 실행한다.  
진행률, 로그, 학습 완료 여부를 확인한다.

### 시나리오 D. 데이터 이상 점검
운영자는 데이터 상태 패널을 보고  
수집 지연, 피처 지연, 모델 미준비 상태 등을 점검한다.

## 10. 핵심 기능 영역

본 서비스의 기능은 아래 5개 영역으로 관리한다.

### 10.1 데이터 수집/저장
- 거래소 데이터 수집
- OHLCV 저장
- 갭 보정
- 데이터 상태 확인

### 10.2 피처/지표 생성
- 기술지표 계산
- 레짐 분류
- 멀티타임프레임 피처 생성
- ML 학습용 target 생성

### 10.3 예측/신호 생성
- 방향 분류 예측
- 수익률 회귀 예측
- 앙상블 스코어 계산
- 현재 신호 산출
- TP/SL/포지션 크기 계산

### 10.4 검증/운영
- 예측 정확도 확인
- 신호 이력 확인
- 모델 상태 확인
- 데이터 품질 확인

### 10.5 UI/대시보드
- 차트 시각화
- 현재 상태 패널
- 하단 분석 패널
- 설정/학습/새로고침 제어

## 12. 운영 목표

현재 단계에서 운영 목표는 아래와 같다.

1. 데이터가 안정적으로 수집될 것

현재 단계에서 이 서비스가 “정리됐다”고 볼 기준은 아래와 같다.

3. 기능 추가 시 범위 포함/제외를 판단할 수 있다.
4. 우선순위 기준이 존재한다.
5. 코드 구조와 제품 구조를 매핑할 수 있다.

## 16. 문서 변경 규칙

앞으로 아래 원칙을 따른다.

1. 코드에 주요 기능이 추가되면 서비스 정의/기능 정의/요구사항 문서를 같이 수정한다.
2. “아이디어”와 “현재 제공 기능”을 같은 레벨로 두지 않는다.
3. 구현되지 않은 기능은 반드시 상태를 표시한다.
4. 공식 범위를 넘어서는 기능은 “추후 확장”으로 분리한다.
